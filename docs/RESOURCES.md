# 资源监测与错误处理

## Windows 监测

- CPU：系统累计空闲、内核、用户时间差值，得到两次采样之间的整机平均使用率。
- 内存：系统可用物理内存，以及 `GetPerformanceInfo` 返回的提交限制减已提交量。不将分页文件可用空间和物理内存简单相加。
- GPU：DXGI 读取显卡名称、LUID 和专用显存容量；英文 GPU 性能计数器按设备 LUID 匹配当前使用率和专用显存占用。GPU 使用率为各引擎汇总后的最大值，不把并行引擎百分比直接相加超过 100%。
- 多显卡：角标显示当前较忙的可识别显卡，悬停可查看所有设备。自动模式仍由引擎选卡，显示的卡不代表已证明是转换使用的卡。
- 后台约每 2 秒采样；窗口最小化后约每 10 秒采样。不要求管理员权限或安装监控软件。
- 不支持的性能计数器或驱动返回不可用，而不是伪造 0%。

## 预检

点击开始后读取有界的文件头或 SOG 的 `meta.json`，不为预检解码整个大文件。支持标准高斯 PLY、SOG 和 SPLAT 的快速估算。压缩 PLY、SPZ、KSPLAT 当前不保证快速元数据识别，仍可直接转换，失败时进入错误处理。

单 SOG 的基础数组按 `点数 × (14 + 球谐系数数量) × 4 字节` 计算，其中球谐 0/1/2/3 阶对应 0/9/24/45 个高阶系数。编码开销用区间估算，并考虑线程数。减点阶段使用输入数据的保守估算，不只看减点后的结果。筛选操作使实际点数不确定时明确标注为筛选前上限。

预检使用本次采样的独立快照，不让常态角标刷新覆盖判断过程。超过 15 秒的采样不用于风险结论。预计高位需求超过物理内存可用量的 88%，或低位需求超过提交余量的 90%，才显示风险提醒。CPU 占用高不触发内存预警。自动 GPU 模式仅在已知设备都有可靠数据、且全部显存余量不足时提示。

这些阈值用于风险提示，不是“必然失败”的断言。用户可以返回调整或继续，不会自动修改画质。预检通过也不能保证运行中资源不会被其他程序占用。

## 错误弹窗

分类覆盖内存分配失败、GPU 资源或设备异常、磁盘满、文件权限或占用、输入文件异常、筛选后无点、未知错误。实际引擎退出保留最近 80 行，而非只保留堆栈尾部。未知错误明确显示原因未确定。

窗口提供返回调整、查看日志和复制诊断。复制内容包含版本、系统、输出格式、设备、线程、估算和原始异常；提交公开问题前请检查其中的本地文件路径是否需要遮盖。

用户主动取消不显示错误框，也不会消耗首次成功求赞提示。转换仍先写临时目标，成功后才提交；若临时目录清理失败，日志会记录路径。

## macOS 源码

CPU 从系统累计时间差分计算。内存余量使用 `memory_pressure` 提供的系统可用比例近似，避免把 macOS 可回收内存误判为已耗尽。Apple 芯片明确标注统一内存，不叠加独立显存。

通用接口不能可靠提供全部 GPU 使用率和显存占用，因此明确显示不可用。源码已同步，但 1.2.0 本轮只构建并实际验收 Windows；Mac 真机行为仍需后续验证。
